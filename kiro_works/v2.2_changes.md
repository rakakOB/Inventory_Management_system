## 2. User management (requirement 1)

Cookie carries the session; Google is only used to establish it.

- `DefaultScheme` = cookie, `DefaultChallengeScheme` = Google, so an
  unauthenticated request redirects **straight to Google's consent screen** as
  specified. `/Login` remains available as an explicit entry point and as the
  landing page when consent fails or is cancelled.
- `OnTicketReceived` checks the email claim against `AllowedUsers` **before** the
  cookie is written. Allowed → `IsPersistent = true`, 14-day sliding expiry.
  Not allowed → logged, cookie cleared, redirected to `/AccessDenied?email=…`.
- `FallbackPolicy = RequireAuthenticatedUser()` protects every Razor Page.
  `[AllowAnonymous]` is applied to `Login`, `AccessDenied`, `Logout` and `Error`.
  `Error` had to be anonymous or a pre-auth failure would redirect instead of
  reporting itself.
- Static files are served before the auth middleware, so the sign-in page can
  load its stylesheet.
- The app **refuses to start** without OAuth credentials, rather than silently
  serving the inventory unprotected.

### What you must do before this runs

1. Add an `AllowedUsers` tab with header `Email` in row 1, one address per row.
   An empty or unreadable tab denies everyone — it fails closed by design.
2. Create an OAuth 2.0 **Web application** client and register
   `<base-url>/signin-google` as an authorised redirect URI for every host.
3. Supply `Authentication:Google:ClientId` / `:ClientSecret` (or the
   `GoogleClientId` / `GoogleClientSecret` environment variables).

Cloud Run stays `--allow-unauthenticated`; enforcement is in the app.

## 3. Reports (requirement 2)

`/Reports` lists eight downloads: Master, the four category inventories,
Suppliers, Usage history, Damage history. Plus **Download All (ZIP)**.

- Data is read live per click; nothing is cached.
- All columns and the header row are included. Ragged rows (the Sheets API drops
  trailing empty cells) are padded to the widest row so columns stay aligned.
- Fields are quoted only when they contain a comma, quote, newline or edge
  whitespace; embedded quotes are doubled.
- Written as UTF-8 **with BOM** so Excel renders `₹` and other non-ASCII text
  correctly.
- The report key is resolved through an allow-list, so the handler cannot be
  coaxed into reading an arbitrary tab.
- In the ZIP, a missing tab is skipped rather than failing the whole archive.

Filenames are `<SheetName>_<yyyy-MM-dd>.csv`.

## 4. Settings (requirement 3)

`/Settings` shows name and email from the Google profile claims, a sign-out
button, a light/dark selector with a live preview, and a placeholder card for
future preferences.

Theme is stored in `localStorage` **and** mirrored to a cookie, and applied by an
inline `<head>` script before first paint so there is no flash of the wrong
theme. It uses Bootstrap 5.3's `data-bs-theme` attribute.

To make dark mode actually work I had to retire some hardcoded light styling:

- The inline `<style>` block in `_Layout.cshtml` moved into `wwwroot/css/site.css`
  and was rewritten against Bootstrap CSS variables.
- `<thead class="table-light">` → `<thead>` across 10 views, with a theme-aware
  `var(--bs-tertiary-bg)` header rule in CSS. `.table-light` is pinned to the
  light palette and looked wrong in dark mode.
- `text-muted` → `text-body-secondary` across the same views.

## 6. Sorting (requirement 5)

| List | Order |
|---|---|
| Master | UniqueCode ascending |
| Electronics / Electrical / Tools / Modules | UniqueCode ascending, then DateOfPurchase ascending (oldest batch first) |
| Used_Components | UniqueCode ascending, then UsedDate descending |
| Damaged_Components | UniqueCode ascending, then DamageDate descending |
| Suppliers | SupplierName alphabetically (unchanged — no UniqueCode exists) |

Sorting uses `UniqueCodeComparer` rather than plain string comparison. A string
sort is *almost* right because codes are zero-padded to three digits, but it
breaks at four digits — `"E-1000"` sorts before `"E-002"`. Comparing the suffix
numerically also tolerates an unpadded code typed straight into the sheet.

## 7. Low stock (requirement 6)

The dashboard's "Low Stock Items" card is gone. Rows are now highlighted on each
category page, with a `Low stock` badge on the component name and an explanatory
note under the table.

**One judgement call worth knowing about.** With batches, "Remaining <
MinStockAlert" evaluated per row would flag every nearly-exhausted batch even
when a full batch sits directly below it. So the threshold is compared against
the **total remaining across all batches of a UniqueCode**, and every row of a
low component is highlighted. That preserves the intent — warn me when a
component is running out — under the new row model.

Threshold falls back to 5 when Master has no usable value. Note that `SafeInt`
cannot distinguish a blank cell from a literal `0`, so a MinStockAlert of `0`
is treated as "missing" and becomes 5. If you need "never alert for this item",
that currently isn't expressible.

## 8. AddStock now appends (requirement 7)

Every submission appends a new row. The upsert branch is gone. The new row takes
quantity into both `TotalQuantity` and `Remaining`, invoice / cost / supplier /
date / remarks as entered, `Brand` from Master (or `-` when Master has none), and
`TotalCost = round(Quantity × CostPerUnit, 2)`.

This deliberately retires the "one row per UniqueCode per category sheet"
invariant, and it fixes the problem flagged in the initial study: a restock used
to overwrite the previous batch's cost and supplier while keeping its invoice and
purchase date, so per-batch cost history was unrecoverable.

## 9. Batch-aware usage and damage (requirement 9)

The component dropdown on `/Usage/Report` and `/Damage/Report` now lists
individual batch rows:

```
E-001 – 10k Resistor (Date: 2026-07-23, Remaining: 10)
```

The deduction is applied to that specific row by `RowIndex`.

**Guard against row shift.** `RowIndex` alone is unsafe: deleting a row anywhere
above shifts every row below it up, so a stale index can point at a different
component. The option value therefore carries `rowIndex|uniqueCode`, and after
the fresh read the code is re-checked against the row actually found. On a
mismatch the submission is refused with an explanation rather than silently
deducting from the wrong component.

The stock hint under the dropdown now reads "Available in this batch".

**History edit/delete.** These reverse stock into the correct batch. The log rows
hold no pointer to the inventory row, only UniqueCode and BatchPurchaseDate, so
`FindByCode` was replaced with `FindBatch(rows, code, batchPurchaseDate)`, which
matches on both and falls back to the first row with the same code if the
original batch row is gone. Log rows are still addressed by their own RowIndex,
which already worked.
